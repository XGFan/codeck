# 撤回的提示词只认 ccrpc 在屏幕上看到的

回复开始前按 Esc 中止时，Claude Code（2.1.318）把这条提示词从对话里拿掉、放回它的输入框，Rewind 选择器里也没有它；transcript 却留着这条提示词与它的 attachment，没有回复、没有 `[Request interrupted by user]`，下一条提示词的 parentUuid 还接在它后面。CoDeck 照文件显示它，在它上面「回退」报「终端的回退列表里没有这条提示词」或认不出界面。

只看 transcript 认不出它：连着很快发出、被一起回答的两条提示词在文件里一模一样（前一条后面直接是下一条，中间没有回复）。按这个形状在本机 2000 个 Session（10845 条提示词）里认出的 10 条全是后者，隐藏它们就藏掉了模型看到过的话。所以只认 ccrpc 看到的：中止的一轮结束时看输入框，显示的正是这一轮的提示词，`turn_end` 就带 `restored_text`；CoDeck 据此在对话记录里找到最后一条、后面没有回复、文字相同的提示词，记下它的 id（按 Session 存于 localStorage）并隐藏，文字放回输入框。

## Considered Options

- **解析层按文件形状判定**（已实现后撤掉）：误判上面那种连发的两条，见上。
- **看 `api-request-blob` 里下一次请求是否还带着这条提示词**：Claude Code 未公开的内部条目，格式随版本变，解析成本也高。
- **索引里记下撤回的 id**（ccrpc 报来后写进索引）：索引是数据根的可丢弃镜像（ADR-0003），重建就丢；要另开一张不随重建删除的表，为一个显示问题不值得。

## Consequences

- 只有 CoDeck 前端知道哪些提示词撤回了：全文索引与 ⌘F 仍会命中它（跳过去时它默认不显示），Session 的标题（撤回的是第一条时）、消息数与统计仍算它，ccrpc 的回退在同样文字的提示词之间对应时仍数它。
- 没有 Connect 时在终端里撤回的认不出来，照常显示；换一台机器或清掉 localStorage 后也会重新显示。
- 记住的是 id、不能在界面上恢复：极少数情况下（回复开始后中止、1.5 秒内有人在终端输入框里打了同样的话、已收到的回复还没进索引）会藏掉一条答过的提示词，只能在「显示系统消息」里看到。
- 带图片的提示词只放回文字（图片成了字面的 `[Image #n]`）。
- 依赖 Claude Code 把提示词放回输入框这一行为与输入框的屏幕格式；Resume 时 Claude Code 是否把撤回的提示词重新带进上下文没有验证。
