# CLAUDE.md

`web`：React 前端（主窗口、终端窗口，以及给 iPhone 的只读 Transcript 页）。命令、数据流、跨模块的规则与约束见根目录的 [CLAUDE.md](../CLAUDE.md)。

本文件里的路径相对 `web/`。这里有：源码 `src/`、静态文件 `public/`、三个入口 `index.html` / `transcript.html` / `terminal.html`、`vite.config.ts` / `tsconfig.json` / `eslint.config.js`、两份 Playwright 配置与用例（`e2e/` 跑在 mock 上，`e2e/host/` 起真实的 daemon）、`.env.mock` / `.env.host`。`package.json` 与 `node_modules` 在仓库根目录，`pnpm` 的命令都在根目录跑；构建产物也落在这里：`dist/`（桌面）、`dist-web/`（iPhone 的对话页）、`dist-e2e/<端口>/`（E2E）。

- `src/ipc/`：ccrpc 与 haa 的 JSONL 协议类型在 `protocol/`（`ipc` 不引用 `features`，ESLint 拦）；`Api` 接口（`api.ts`）有三套实现——`real.ts` 包装生成的 bindings，`src/mocks/`（`index.ts`，另有 `ccrpc.ts` / `haa.ts` / `plan.ts`）用 `src/mocks/data/*` 的内存数据，`remote.ts` 经 daemon 的 HTTP + WebSocket（`remote.test.ts` 核对它与 bindings 的方法名、参数名一致），在 iPhone App 里改走 App 中转（`nativeTransport`：RPC 经 `webkit.messageHandlers.codeckRpc`，事件由 App 调 `window.codeckPage.event` 推入；有 `codeckRpc` 时 `ipc/index.ts` 选用它；`window.codeckPage` 上的 `event` 与 `state/native.ts` 的 `setConnect` 往同一个对象上加）。`VITE_IPC=mock`（`.env.mock`，即 `pnpm dev:mock`）切到 mock，`VITE_IPC=remote`（`.env.host`，`vite --mode host`）切到 remote；`transcript.html`（`TranscriptPage.tsx`）是 iPhone 的只读 Transcript 页，只渲染对话记录，Connect 与输入都在原生端。**E2E 全部跑在 mock 上**（tauri-driver 不支持 macOS），所以新增/修改 IPC 能力时要同步 `src/mocks/` 的实现和 mock 数据。
- `src/queries/`：TanStack Query hooks 与 `queryKeys`；`events.ts` 订阅后端事件并做节流失效（实时追随、统计刷新）。
- `src/state/ui.ts`：zustand 的 UI 状态；按 Session 的状态（branchChoices、panelStack、⌘F、展开状态等）在切换 Session 时重置；展开状态的键统一由 `features/transcript/keys.ts` 生成；栏的收起状态（`collapsed`）是全局的，存 localStorage。
- 配色：`lib/theme.ts` 按设置（自动 / 浅色 / 暗色，存 localStorage）在 `<html>` 上写 `data-theme`，`index.css` 的暗色变量、Tailwind 的 `dark:`（`@custom-variant`）、图表与 Shiki 都按它，不直接用 `prefers-color-scheme`；`public/theme-init.js` 在首次绘制前套用；窗口本身经 Tauri 的 `setTheme` 跟着切换。
- 尺寸：`index.css` 把根字号设为 13px，Tailwind 按 rem 的尺寸类会跟着缩小（`h-8` 是 26px、`h-7` 是 22.75px）；要和像素对齐的地方（侧栏的行高、和计算挂钩的高度、图片块）写成 `h-[28px]` 这样的像素值。
- 滚动条：`index.css` 自定义 `::-webkit-scrollbar`，`lib/scrollbars.ts` 在滚动时给元素写内联 `--scroll-thumb` 让滑块显示。WebKit 只在内联 style 变化时重绘自定义滚动条，改 class/属性不生效。
- `src/features/*`：各功能模块；对话渲染在 `features/transcript/`（TanStack Virtual 虚拟列表，`nodes/` 节点渲染，`tools/` 工具渲染器，列表的贴底跟随、滚动请求等在 `listHooks.ts`）。Connect 的 `state/` 放连接状态与存储，`composer/` 放输入框，`requests/` 放请求卡片，`rewind/` 放回退与 Fork。Connect 的状态在 `features/connect/state/store.ts`，ccrpc 连接的命令与事件分发在 `state/client.ts`（可注入 api 与计时器，单测见 `state/store.test.ts`），`ccrpc ls --watch` 的启停在 `state/lsWatch.ts`，草稿持久化在 `state/drafts.ts`，Code Mode 下代码运行期间的调用（ccrpc 的 `code_call`）并进对话记录在 `state/codeCalls.ts`（纯函数，经 `useShownTranscript`）；输入框里的图片块是文本框里带不可见起止符的一小段文字（`state/imageTokens.ts`，纯函数：编号、拆成 `parts`、清理残缺块），由文本框下面的副本画成整块、悬停与拖动在 `composer/ImageChips.tsx`。haa Worker 状态条在 `features/haa/`（仅桌面端，`VITE_IPC !== "remote"` 门控）：`src/ipc/protocol/haa.ts` 宽容解析 JSONL、`store.ts` 在当前 Session 是 Live 或已 Connect 时让 Host 启动 watch，以递增的 `id` 归属事件并串行协调启停（失败或退出后本轮不重试，停用即清空快照）；状态条只显示 `owner` 等于当前 Session ID 的 haa Worker、`HaaBar.tsx` 渲染列对齐表（排序、时长、Task 列文字、收起摘要等是 `view.ts` 里的纯函数；有 `ls` 给的 `sessionId` 的行——agy 的 Worker 要它的对话在 Session 列表里，codex、pi 的 Worker（`view.ts` 的 `readsWorkerById`，按模型名的后端）对话由后端按 id 从它们自己的记录读——点了在右侧面板打开它的对话，用的是 `panelStack` 的 `haa:<id>` 项；面板对后者没有 Session 详情，指标取 haa 的数据，Worker 在干活时每 2 秒重读），`ConnectRoot` / `ConnectPanel` 挂接它并在 Live 未 Connect 时复用 `FloatingFoot` 维持 `--connect-h`；mock 与 E2E 探针（`window.__cvHaa`）在 `src/mocks/haa.ts`。订阅额度在 `features/quota/`（仅桌面端）：`model.ts` 是纯函数（四种状态：读取中 / 有 / 没有订阅额度 / 失败；一项额度的显示；侧栏按钮的色调；周期锚），`usePlanUsage` 是统计页的额度条、侧栏左下角的统计按钮与它的浮层共用的一个查询（前台每 5 分钟、回到前台过期则重取，刷新走 `getPlanUsage(true)`），`useCycleRule` 给出「本周期」的规则——有额度时以每周重置时刻（取整到分钟）为锚、每 168 小时一段（锚存 localStorage 的 `codeck.planCycleAnchor`，读取中或失败时沿用存的），确知账号没有订阅额度时才清掉锚、用设置里的每周重置（`lib/cycle.ts` 的 `CycleRule`）；mock 与 E2E 探针（`window.__cvPlan`）在 `src/mocks/plan.ts`。统计页在 `features/stats/`：时间范围在 `range.ts`（天 / 周期 / 月份 / 最近 N 天 / 全部；除「全部」外查询总带上下界），用量、使用频率、用量走势与单日的 Session 时间线的聚合都是纯函数（`usage.ts` / `frequency.ts` / `trend.ts` / `daySessions.ts`），小时格、月块与 Session 时间线是 DOM（格子的提示是 `FreqTip.tsx`），柱状图与走势用 ECharts；切换范围等新数据时用上一份数据连同它自己的范围继续画（`index.tsx` 的快照）。「已完成」与通知由 Host 判断（`crates/codeck-host/src/attention`，ADR-0019），`features/attention/` 只做两件事：`useAttention`（挂在 `ConnectRoot`）在窗口焦点、可见性与切换 Session 时把正在看的 Session 报给 `set_viewing`（失焦、隐藏报 null），收 `attention-event` 存「已完成」（重新载入时 `attentionDone` 取回），`useDone` 读它；续缓存的 `keeping` 留给 Dock 角标与「别处在等」。前端不发通知：点通知时外壳把窗口带到前面并发 `notification-click-event`，前端经 `Api.onNotificationClick` 走 `codeck://` 链接同一条路。设置 › 通用的通知时长、补推与 Bark 读写 Host 的 `notify_settings` / `set_notify_settings`；旧版存在 localStorage 的 `codeck.notify` 启动时搬过去（`migrate.ts`）。mock 按 `setLive` 的状态变化与 `setViewing` 模拟 Host 的「已完成」。侧栏（Live / Project / Recent）在 `features/sessions/`：分组、展开、定位与高度分配是 `groups.ts` 里的纯函数，组件在 `Sidebar.tsx`，已添加的 Project 存在 settings.json 的 `sidebarProjects`。Shiki 在 Worker 中运行（它用到的 shiki 模块列在 `vite.config.ts` 的 `optimizeDeps.include`，否则 Vite 运行中预构建会整页刷新）。`@/` 指向 `src/`。E2E 的公共 helper 在 `e2e/helpers.ts`（进页面后马上按快捷键的用 `openApp`，它等首次渲染把快捷键挂上），Connect 的（`connectTo`、`probe`、`lastSent` 等）在 `e2e/connect-helpers.ts`。
