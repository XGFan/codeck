# CLAUDE.md

`crates/codeck-host`：Host 的运行时（worker、监听、设置、ccrpc、Connect 状态、局域网服务）与 headless daemon；无 tauri 依赖。命令表怎么加命令见根目录 CLAUDE.md 的「跨模块的规则」。命令、数据流、跨模块的规则与约束见根目录的 [CLAUDE.md](../../CLAUDE.md)。

- `crates/codeck-host`：`Host::start(HostConfig, 事件 sink)` 启动一切；路径（缓存、settings.json、ccrpc 日志、图片）由 `HostConfig` 注入，`HostConfig::desktop()` 即桌面的原路径。事件是 `HostEvent`（名字与载荷同 tauri 事件，desktop 有测试对照）。
- daemon 是 `codeck-host` 包自己的可执行文件（`src/bin/codeck-host.rs`，`cargo build -p codeck-host`），只是命令行外壳；HTTP 服务在库的 `lan/`，daemon 一直提供，桌面在「局域网访问」打开时提供（`lan/mod.rs` 的 `LanService`，开发时 `CODECK_LAN_PORT` 可换端口）。axum；`/health`（`apiVersion`）、`POST /v1/rpc {method, args}`（args 的键同 tauri invoke 的 camelCase）、`/v1/events`（WebSocket，先发 `hello`，不保留历史，客户端每次连上都整体重新同步）、`/web/*`（`--web-dir`，即 `web/dist-web`）。默认只监听局域网网卡（按名字白名单：`en*`、`eth*`、`wl*`）的私网 IPv4，每 5 秒按当前地址增减监听（`--listen` 指定时不跟随）；校验来源子网与 Host 头（只认监听的 IP，防 DNS 重绑定），`/v1/rpc` 只收 `application/json`，拒绝 `Origin: null` 与不认识的 Origin，`/web/` 带 CSP（`net.rs`、`server.rs`）。非回环监听只讲 HTTPS、要鉴权（ADR-0017）：`lan/tls.rs` 的自签证书在 settings.json 旁的 `tls/`（缺一半或不配时报错、不重新生成，否则已配对设备全部失效），`TlsListener` 在 `accept()` 里并发握手（上限 64、各 10 秒），交给 `axum::serve` 前要套 `.tap_io(|_| ())` 才能用 `ConnectInfo<SocketAddr>`；`lan/security.rs` 的 `LanSecurity` 用一把锁串行设备表（`devices.rs`，`devices.json` 只存 token 的 SHA-256）与配对报价（`pairing.rs`，内存里、单调钟 5 分钟、兑换成功写盘后才作废）；`server.rs` 的 `check` 在子网、Host 头、Origin 之后只放行 `GET`/`HEAD /health` 与 `POST /v1/pair`，其余要 `Authorization: Bearer`，移除设备经它的撤销信号断开 WebSocket（整段 relay 在 `select!` 里）与响应头还没发出的请求；`Serving` 对非回环子网没有 `LanSecurity` 就拒绝监听，回环照旧明文、不鉴权（开发与 E2E）。daemon 的 `pair` / `devices` / `unpair` 子命令经状态目录的 `control.sock`（`lan/control.rs`）与运行中的进程交互：状态目录不能是空路径或根目录，须是本用户的、不是符号链接，每一级上级目录属主是 root 或本用户、组或其他用户可写的须带 sticky 位，设为 0700 后复核（`devices.json` 与 daemon 的 `settings.json` 同样拒绝符号链接、别人的或组/其他用户可写的文件）；`LanSecurity::open` 对 `daemon.lock` 取 flock（桌面与 daemon 都取，防两个进程共用一份设备表）；两端核对对端 uid；路径超过 unix socket 上限时启动即报错；初始监听成功后才绑定 socket，只删本实例绑定的那个。撤销在 `gated` 与 WS relay 里用 `biased` 优先；连接预算全进程共享（`tls.rs` 的 `process_conn_limits`，总 128、每个来源 IP 16），TLS 连接在没有在途请求时 180 秒没有读到数据即关（请求体读完后暂停计时、应答后重新计时：hyper 等应答时仍轮询读，不暂停会截断 150 秒的 connect_command）；配对链接最多 4 个地址；兑换先在锁外写临时快照、持状态锁复核报价后才 rename 发布；状态目录逐个分量校验符号链接；`/v1/pair` 的 10 秒只管读请求体，进入兑换后返回真实结果；`LanSecurity` 的写盘（IO 锁）与内存状态（状态锁）分开，鉴权不被写盘阻塞；设备表与 `tls/` 拒绝符号链接与别人的文件，`key.pem` 宽于 0600 报错。状态目录与桌面分开，开发时也别指向桌面的目录。
- Connect 状态（`HostConfig.track_connect`，daemon 与桌面都开）：`connect/state.rs` 把 ccrpc 的行归约成 `ConnState`（`web/src/features/connect/state/conn.ts` 规则的 Rust 版，改一边要对照另一边；Code Mode 的 `code_call` / `code_call_end` 两边都折叠成 `codeCalls`，Host 只留最近 50 个、序列化超过 4KB 的返回值不留，iPhone 经 `setConnect` 把它交给对话记录页），`connect/mod.rs` 的 `ConnectHub` 推 `connect-state-event` / `connect-removed-event`；折叠只跟 ccrpc 的事件走（协议 6）：请求事件按 `request_id` 增改、`request_end` 删除、Session 结束或更换时清空，排队项与后台任务照 `queue` / `tasks` 事件原样存，Host 不轮询、也不折叠命令的响应；远程方法 `connect_states` / `ccrpc_ls` / `connect_shared` / `connect_command` 不在命令表里（不是 tauri 命令）。格式由 `tests/conn_state_golden.rs` 与 `ios/Tests/Fixtures/conn-state.json` 钉住。`ccrpc ls --watch` 的常驻由 `keep_ls_watch` 决定：daemon 启动即开，桌面在「局域网访问」打开期间才开，这期间前端的启停不动它、只补发缓存的列表。桌面窗口的 Connect 状态仍由前端自己折叠（ADR-0012）：只有远程发起或关闭的连接才发 `CcrpcRemoteConn` / `CcrpcClosing` 让前端认领或放手，前端重新载入时用 `connect_snapshot` 取回已有的连接。
- `worker.rs`：单个后台 worker 通过 channel 消费 `Job`（FullScan / Fs 批次（排队中的合并成一个）/ TextBacklog / Rebuild / SetRoot / SwapRoot（切换数据根：在两个任务之间换 Engine，命令等它回复）/ Rescan / RefreshPrices / ApplyPrices）。Live 轮询不排进 worker：计时线程每 3 秒直接读进程文件，免得排在索引后面、又打断全文积压。全文索引积压 `TextBacklog` 在空闲时运行，任何其他任务入队都会让它在当前事务提交后让位——改调度逻辑时注意别造成互相重新入队的活锁（曾出现过）。
- `keepalive.rs`：缓存保活。`cv-keepalive` 线程每 30 秒用 `Engine::live_now`（不动 `poll_live` 比较用的快照）看 Live Session。「上次用到」是 transcript 末尾最后一条 `api-request`（带 TTL 与 beta，按文件大小与修改时间缓存，不重复读）与上次续成（缓存目录的 `keepalive.json`）的较晚者；`due`（纯函数）挑出 1 小时缓存、满设定时长、离过期 3 分钟以上、5 分钟内没试过的。再 `ccrpc ls --json` 确认在 clay 里、有插件、空闲（进程文件的状态按 `LiveStatus::from_raw` 读，`shell` 也算）、空闲压缩关着（读 `claude_pid` 的 argv：macOS 用 `KERN_PROCARGS2`、Linux 用 `/proc/<pid>/cmdline`，按 claude 的顺序看 `--settings` 与各层设置里的 `idleCompaction`）；不发时原因写进 gui.log（同一原因连着只写一次），没续成不算续过。然后发 `/btw ping, just say pong.`：有连接的经 `ConnectHub::command`（等答案用 `observe` 看行），没有的临时 `ccrpc attach`。这条 `/btw` 按问题开头的 `ping, just say pong` 认出（Rust 的 `keepalive::MARKER` 与 `state/conn.ts` 的 `isKeepAlive` 要一致）：Host 的 `ConnState` 与前端 `state/conn.ts` 都不当作请求；前后发 `KeepAlive` 事件（不转发给 LAN），前端 `features/attention` 在这期间不把它的等待作答当真。保活开着时，`ccrpc/launch.rs` 的 `Launch`（CoDeck 启动 claude 的参数都从它来：新建、Resume、Fork 与 `codeck new`）往 claude 的设置里合进 `"idleCompaction": false`（启动规则里有 `--settings` 就合进最后一个，文件读出后以 JSON 传；没有才另加一个）：claude 的空闲压缩不理 `/btw`。
- `prices.rs`：下载 LiteLLM 价格表；worker 的 `RefreshPrices` 在独立线程里下载，结果以 `ApplyPrices` 交回 worker 写库，价格有变化时发 `PricesChanged` 事件。
- `watcher.rs`（notify：macOS 上是 FSEvents，Linux 上是 inotify；debounce 后发 `Fs` 任务）、`state.rs`（持有可整体替换的 Engine，切换数据根时 swap）、`settings.rs`（数据根覆盖等，路径由 Host 启动时设定）、`events.rs`（`HostEvent`：IndexStatus / SessionsChanged / LiveChanged / PricesChanged，ccrpc 的 CcrpcLine / CcrpcExit / CcrpcLs / CcrpcLsEnded，以及 ConnectState / ConnectRemoved / CcrpcRemoteConn / CcrpcClosing）。
- `ccrpc/`：Connect（ADR-0007）。每个连接一个 `ccrpc attach|new` 子进程，stdout 逐行原样转发为 `CcrpcLine` 事件（协议的类型在前端 `web/src/ipc/protocol/ccrpc.ts`，解析与状态在 `features/connect`），三层日志在 `~/Library/Logs/dev.joy.codeck/ccrpc/`（daemon 在它的状态目录下）。桌面的 ccrpc 状态在第一个 ccrpc 命令时才初始化（要跑一次登录 shell 取环境），不要挪到桌面启动流程里（「局域网访问」打开时例外，要常驻 `ccrpc ls`）；daemon 启动即初始化。可 Connect 的 Session 列表由常驻的 `ccrpc ls --json --watch` 推来（`relay.rs` 的 `watch_sessions`，一次只有一个）。对话内容不走 ccrpc，仍由索引与 Live 跟随提供。
- `plan_usage.rs`：订阅额度（ADR-0016，`local fn get_plan_usage(refresh)`）。起一个无界面的 claude（`-p` + stream-json，不加载 MCP 与 hooks，不发提示词），在控制通道上发 `get_usage`，读到应答就关；首次调用时才取登录环境（同 haa），15 秒超时，独立进程组，同时只跑一个，成功的结果（含「没有订阅额度」的 `None`）缓存 60 秒，失败不缓存，`Host::shutdown` 时杀掉在跑的。`get_usage` 是实验性接口，解析宽容（只取认识的字段）。这个进程的工作目录是 `<缓存目录>/plan-usage`，`Engine::read_process_files`（所有 Live 判断共用）丢掉 cwd 等于它的进程文件，免得它闪现成 Live Session；别人用 `claude -p` 跑的 Session 不受影响。
- `haa.rs`：桌面端 haa Worker 状态推送（`local fn haa_watch(on, id)`，事件 `HaaWorkers` / `HaaWatchEnded` 不转发给远程 LAN），写法同 `ccrpc/relay.rs` 的 `watch_sessions`：一次只有一个 `haa ls --all --json --watch` 子进程，stdout 逐行原样转发，关它的 stdin 就结束（2 秒后还没退出才 kill），自己退出时发 `HaaWatchEnded`（原因取 stderr 第一行）。首次 `haa_watch(true, id)` 时才取登录环境并找可执行文件（`ccrpc/env.rs` 的 `tool_path`，与 ccrpc 同一套顺序：`CODECK_HAA` → `~/.local/bin/haa` → `PATH`），不放进桌面启动流程。
