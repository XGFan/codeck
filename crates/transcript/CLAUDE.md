# CLAUDE.md

`crates/transcript`：解析库，读 Claude Code 的数据（transcript、进程文件、价格）并组装成显示模型；无 SQLite、无 tauri，codeck-core 与 ccrpc 都用它。命令、数据流、跨模块的规则与约束见根目录的 [CLAUDE.md](../../CLAUDE.md)。

- `crates/transcript` 放解析层：`raw`、`parse`、`known`、`assemble/*`、`model/*`（组装用的类型）、`live`（进程文件）、`layout`（Session 目录里 agent 与 sidecar 文件的位置，codeck-core 的扫描与 ccrpc 共用）、`pricing`。codeck-core 直接写 `transcript::…`。解析层的集成测试（parse / merge / branch / assemble / code_mode，共用的辅助函数在 `tests/support/`）在 `crates/transcript/tests/`，fixture 用 codeck-core 的，经 `#[path]` 引用 `crates/codeck-core/tests/common/fixtures.rs`（该文件不能依赖 codeck-core）。解析层的错误是 `TranscriptError`，codeck-core 按变体映射到 `CoreError`。
- Code Mode（Claude Code 的 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE`，规则见 spec「Code Mode」，各部分在哪、哪些可删见下面「Code Mode」一节）：解析与对原始格式的判断只在 `assemble/code_mode.rs`（事件解析、按路径把虚拟消息归给代码）；模型里代码仍是一个 `REPL` 的 `ToolCall`（`code` 带 `callCount` 与返回值），它调用的工具是同一条消息里紧随其后的平级 `ToolCall`（`viaCode` 指回代码），前端、⌘F、CLI 都按这个平的序列走，不要再嵌套。
- haa 的 agy Worker（ADR-0021）：`agy.rs` 是唯一知道 agy 原始格式的地方（`brain/<id>/.system_generated/logs/transcript_full.jsonl` 的位置与 step；`find_transcript` 按 id 找文件）。`adapt` 把 step 译成 `RawEntry` 直链：用户 step 只取 `<USER_REQUEST>` 之间，工具结果按顺序配对，工具译成 Bash / Read / Edit / Write / TodoWrite / WebSearch 并在 input 的 `agyOriginal` 里留原调用，认不出的 step 照原文显示为认不出的条目；`offset` 是胜出那一行的字节位置（`raw_line` 读回原行）。别处不读 agy 的字段；测试在 `tests/agy.rs`（含 `#[ignore]` 的真实数据探针，读 `CODECK_AGY_ROOT`）。
- haa 的 codex / pi Worker（ADR-0020、ADR-0021）：`codex.rs`、`pi.rs` 各是唯一知道那边格式的地方（`thread_of_path` / `session_of_path` 与 agy 的 `session_of_transcript` 给 codeck-host 的 watcher 从路径认出对话 id），`foreign.rs` 是两者共用的找文件、切完整行、派生 uuid（`derived_uuid`，agy 的 `make_uuid` 也用它）与造 Claude Code 条目的工具，不知道任何一边的格式。codex 只译 `event_msg` / `item_completed`（codex 界面显示的那一份），`response_item` 不看；`.jsonl.zst` 用 ruzstd 解压。pi 沿 `id` / `parentId` 建树，跳过的条目（`QUIET_TYPES`）把父节点传下去。测试在 `tests/codex.rs`、`tests/pi.rs`（内联数据，另有 `#[ignore]` 的真实数据探针，读 `CODECK_CODEX_ROOT` / `CODECK_PI_ROOT`）。
- Teammate 与其他 Agent、插件转发来的消息（`<teammate-message>`、`<cross-session-message>`、`<agent-message>`）只在后端拆：`prompt::relayed_messages` 给出 `UserPrompt.relayed`（发送方、颜色、summary、正文、一行预览、Teammate 的 JSON 消息说的事），前端 `features/transcript/teammate.ts` 只管排版，不读标签。两处例外：mock 数据按记录的原文写，`web/src/mocks/data/relayed.ts` 替后端拆（改格式时对照 Rust 的测试）；Connect 的排队提示拿到的是 ccrpc 给的原文，`connect/composer/queue.ts` 只读开头标签的发送方与 summary。
