# 与人共用 Pane，读不懂屏幕时才调尺寸

ccrpc 连着的 Pane 同时显示在调用方的界面（CoDeck）与人的 ToH Client 里，两边都能输入。PTY 尺寸归人的 Client：ccrpc 附着时订阅 Holder 的 PTY 尺寸（Size 帧），VT 跟着它走，自己不发 Resize。只有屏幕在这个尺寸下读不懂时（等待中的对话框认不出、审批框的选项读不全、写入前等不到输入框、命令报 `unrecognized_screen`），ccrpc 才把 PTY 调成 120×40，等 Claude Code 重画后再读；调过不调回去，人的 Client 下次抢尺寸（切到前台、按键）就换回它的尺寸。

120×40 取的是常见终端的尺寸：Claude Code 的界面按大多数人的终端排版，在这里认得最稳。80×24（ToH 缺省）太矮，反馈草稿卡片会把输入框挤出屏幕；160×48 比多数人用的大，没必要。`new` 也以它为 PTY 初始尺寸，hidden 的 Pane 没人显示，就一直是它。

## Considered Options

- **ccrpc 持有尺寸，人接手就只读**（原先的做法）：附着后发 Resize 成为尺寸所有者（160×48），所有者被人拿走就发 `taken_over`、只读，`reclaim` 取回；另有 `--co-display` 共显模式不发 Resize、不判接手。CoDeck 一直只用共显，独占模式没有调用方；而共显在人的窄屏下读不出对话框，又没有办法补救。合成一种：始终共显，读不懂时才调尺寸。
- **每次读屏、写入都调成 120×40**：读屏一直在做，挑不出「读的时候」；大部分写入（经插件作答的审批与提问、粘贴提示词、Esc）与尺寸无关。改尺寸会让 Claude Code 整屏重画，人那边画面跳动；而且改尺寸会改变对话框本身（computer use 的授权框在窄屏下只授权列得下的应用），识别、上报与作答必须在同一尺寸下完成。
- **按 max(当前尺寸, 下限) 只补不够的那一维**：组合出来的尺寸（如 200×40、120×60）不是 Claude Code 常见的排版，不如固定一个常见尺寸。
- **调完再还原成人的尺寸**：ToH 没有「交还尺寸」，ccrpc 只能按原来的尺寸再发一次 Resize，还要处理期间人又改了尺寸；人的 Client 下次操作本就会抢回尺寸，不值得。

## Consequences

- 人在窄屏上看着时 ccrpc 调了尺寸，那一端会看到按 120×40 排版的画面，直到它的 Client 抢回尺寸后 Claude Code 重画。
- 写入期间人也在打字会撞车：ccrpc 粘贴前清空输入框，人打了一半的字会被清掉。
- ToH 升级前就开着的 Pane（Holder 不发 Size 帧）不能连，要关掉重开（ToH ADR-0051 取代了原先的尺寸所有者通知）。
- 已按过键的命令读不懂屏幕时只调尺寸、报错，不自动重试（重试可能重复按键）；调用方再发一次即在 120×40 下读。
