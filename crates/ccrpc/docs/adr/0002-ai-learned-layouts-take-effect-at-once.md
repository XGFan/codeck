# AI 分析出的布局立即生效

ccrpc 认屏幕原先只认实测过、写死在识别器里的布局，认不出就发 `unrecognized`、不按键；Claude Code 一升级改了界面文字，就要人拍屏幕、改代码。现在识别器改为按布局库识别：内置布局来自实测，认不出的屏幕交给分析器（ccrpc 自己调 Anthropic 兼容接口，缺省 DeepSeek，发整屏文字和挂起工具的输入），分析得出的布局存进本机布局库，**立即**用来识别与按键，不等人确认。审批归为 `permission_request`，提问归为 `question`，其余带编号菜单的界面归为 `choice`。

## Considered Options

- **分析结果先待人确认**：最稳，但每种新界面第一次出现时都要人在场，和“无人值守地驱动 Claude Code”的用途相悖。
- **只有不涉及授权的界面自动生效**：要靠模型判断“涉不涉及授权”，判断本身就是最容易错的地方。
- **由调用方分析**：ccrpc 不依赖模型，但每个调用方（包括没有 AI 的 ToH Client）都得会做这件事。

## Consequences

- 模型理解错时会按错键。兜底是按键前的结构检查，不依赖模型：审批类布局必须同时有允许与拒绝、transcript 里有对应的挂起工具调用、选项编号与屏幕一致，过不了照旧 `unrecognized`。
- 屏幕上的代码、命令、diff 乃至密钥会发给分析器所用的模型服务。
- 学到的布局只在本机；要成为内置布局（进仓库、有单测保护），需用导出命令。
