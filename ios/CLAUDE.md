# CLAUDE.md

`ios`：iPhone App，经局域网浏览与 Connect 一台 Host（ADR-0011、ADR-0012）。命令、数据流、跨模块的规则与约束见根目录的 [CLAUDE.md](../CLAUDE.md)。

- SwiftUI，iOS 17+，`ios/project.yml` 用 xcodegen 生成 `CoDeck.xcodeproj`（生成物也提交；改了 project.yml 或增删文件后重新 `xcodegen generate`）。尽量原生：列表、导航、Session 页的悬浮顶栏与底部浮层、输入框、请求面板（审批/提问/选择）、后台任务都是 SwiftUI；只读的 Transcript 是 WKWebView 加载 Host 的 `/web/transcript.html`，但页面不直接连 Host（ADR-0017：WKWebView 对页面的 WebSocket 不能放行自签证书）：地址是 `codeck-web://host/web/transcript.html`，`Views/HostSchemeHandler.swift` 的 scheme handler 用固定指纹、带 token 代取 `/web/` 下的 GET，`codeckRpc`（带应答的消息处理器）转发 RPC，事件由 App 在页面真正 `ready` 后推给 `window.codeckPage.event`（先推一条合成的 `hello`）；两个消息处理器只认主框架与 `codeck-web://host`，主框架只能导航到 transcript.html；每个 WebView 在创建时记下 HostModel 的代际与当时的 client，入口与回调完成前都核对（换 Host 后旧页面拿不到新 Host 的凭据），详情页按代际重建 WebView，数据存储非持久化。外部 `codeck://pair` 先 `resolve`（不带凭据探测）再按实际地址确认，然后 `pair(with:at:)`。
- `Sources/Host/`：地址（只收私网 IPv4，DEBUG 版另收 127.0.0.1）、`PairingLink`（解析 `codeck://pair`）、`HostStore`（UserDefaults 的 `codeck.host` 记地址与证书指纹，token 在钥匙串）、`PinnedSession`（只认配对时的证书指纹；只实现 task 级的证书质询，按 task 归因指纹不符）、`HostClient`（`/health` 校验 `apiVersion`、RPC、`/v1/pair`，除这两个外都带 `Authorization`）、`EventStream`（WebSocket；每个 `hello` 都整体重新同步；退到后台断开、回到前台重连）、`HostModel`（配对的步骤是可注入依赖的 `executePairing`；切换 Host 按代际丢弃旧结果；401 与证书不符进 `needsPairing` 终态，只给「重新扫码」）；扫码页是 `Views/HostSetupView.swift` + `QRScannerView.swift`（AVFoundation），`codeck://pair` 链接在 `CoDeckApp` 的 `onOpenURL` 里先确认再配对；`Sources/Connect/` 是 Connect（状态来自 Host 的 `ConnState`，命令都经 `connect_command`）。文案与桌面一致（状态词、权限模式等），术语按 CONTEXT.md。
- 模拟器测试：`xcodebuild … test`；`HostProbeTests` 只在 `TEST_RUNNER_CODECK_PROBE=<IP>:<端口>:<指纹>[:<token>]` 时对真实 Host 运行（固定指纹的 HTTPS、WSS 与 401 归因）。手动联调：明文用 DEBUG 版手输 127.0.0.1 连 `--listen 127.0.0.1` 的 daemon；TLS 与配对让 daemon 监听 en0（独立的端口与 `--state-dir`），`codeck-host pair` 打出的链接用 `xcrun simctl openurl booted <链接>` 喂给 App（会弹系统的「在 CoDeck 中打开」）。
